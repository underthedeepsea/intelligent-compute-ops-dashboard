# 发布与回滚检查单

当前部署配置见 [部署说明](../deploy/README.md) 与 [生产准备项](deployment-production-checklist.md)。本清单用于目标环境验收，不以页面可打开替代数据来源和持久性验证。

## 发布前

- 保存源码版本、依赖锁、迁移状态和静态资源版本。
- 停止 API、worker 及其他数据库写者，备份数据库与外部数据目录；验证备份可恢复。
- API/Web 来自同一版本；SQLite API 单副本、单 sync worker，维护任务串行执行。
- 配置随机 Django 应用密钥、Host/origin、同源 API 与部署入口访问控制。
- 核对 NAS UID/GID、锁及持久性；准备适合目标 CPU 架构的镜像。
- 演示包通过独立外部目录安装。普通入口保留真实、未知、缺失和过期来源；显式回放使用固定 SYNTHETIC 窗口。
- 实际巡检接入另核对只读身份、实体绑定、字段单位、来源和采样窗口。

## 发布顺序

1. 停写并备份，记录恢复点。
2. 串行执行迁移；需要演示目录更新时先预检，明确应用后执行 `check_scene_install`。
3. 启动匹配的 API/Web，检查 `/healthz`、`/readyz`、五屏、控制台和资源版本。`/readyz` 只验证数据库连接。
4. 核对异常对象、业务关联、空态、暂停与静态可读性，以及原始采样时间。
5. 真实监控另做断流、来源拒绝、过期和目标环境稳定性验收；目录导入不代表真实链路已经接通。

## 回滚

停止写者并保存错误日志，恢复匹配的上一版 API/Web；需要还原数据库时使用已验证备份，明确备份后数据差异。不要自动覆盖升级后新增目录，不用演示数值替代缺失的生产观测。恢复后再次检查目录可读、绑定和来源有效、旧遥测不会被标为新鲜。
